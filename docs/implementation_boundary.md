## 运行地点与环境

- 本机：源码编辑、阅读、Git 操作，以及配置、语法、可独立导入的接口、小规模 CPU 数值/形状/梯度调试。梯度检查用于验证模块，不进行优化器训练。
- 服务器：CUDA 扩展构建与验收、GPU 整网前反向、真实数据完整闭环、mini/短训练、正式训练、显存/吞吐测量和正式实验评价。
- 本机不启动任何实际训练，包括 CPU/GPU、mini、少量样本或仅若干步的训练。
- 现有 WSL、venv、构建副本、脚本和成功报告作为历史记录保留，不自动成为当前执行安排。不因本次说明更新重装、升级或删除环境。
- 服务器需按实际设备重建环境和重新验收；本机已有报告、venv 和编译产物不能代替服务器证据。

## 第一版技术范围

- 固定版本 FutureDet 是执行主体，优先复用其数据、标签、训练循环、检查点、递归未来预测头、解码与评价，按明确接口差异适配。
- PillarNet 提供柱体编码、稀疏主干与 native 算子参考。两个 det3d 包不能混入全局 PYTHONPATH；统一导入和注册是 L1 的内容。
- 助手按论文实现或适配 Stage5、A-FPN、DIoU、激活与 GT sampling 调度；每项拆成独立、可审核的小任务。
- 完整重写 runner/SDK、旧权重转换、AMP、多 GPU、算法改进和新增框架不属于默认首版任务，确有需要时另提范围。
- 原始旧工程和 references/ 保留；工作副本的位置、文件来源和必要差异先说明，再实施。

## 小任务确认与审核规则

1. 动手前提交本批任务说明：一个具体目标、拟新增/修改文件、调用关系或输入输出、来源与依据、未决假设、预计改动量、检查命令与运行地点、完成标准。
2. 用户明确确认本批后才修改实现。路线或里程碑获得认可，不等于授权一次性完成全部后续代码。
3. 每批只完成一个可审核目标，优先控制在少量相关文件。文件数和行数用于说明规模；较大模块或大段上游移植先拆批，不能通过改名、移动文件或复制代码绕过范围。
4. 已确认范围内的实现和必要修复可完成；出现新模块、额外依赖、跨模块重构、范围扩大、论文/评价协议变化时，先解释并取得对应确认。
5. 完成后交付实际改动清单与差异、关键代码讲解、来源与假设、实际检查命令/结果、未验证项和下一项建议；停在本批，等待用户审核及明确继续。
6. 将 Git/GitHub 和工程框架讲解绑定本批具体改动；提交/上传的内容和操作在对应任务范围内说明，不把本地保存或登录成功写成已上传。
7. 辅助代理仅做已批准范围内的工作；默认用于只读调研/审查，不借并行执行提前实现尚未批准的模块。
